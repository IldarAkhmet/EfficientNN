HW1 — Analytical performance model of a small CNN

В этой работе я построил простую аналитическую модель для небольшой CNN и сравнил её с реальными измерениями на GPU.

Нужно было получить четыре функции:

flops(image_size, batch)
memory(image_size, batch)
latency(image_size, batch, theta)
energy(image_size, batch, theta_energy)

Для FLOPs и memory формулы выводятся напрямую из архитектуры сети.
Для latency и energy используются дополнительные параметры theta, которые подбираются по реальным измерениям на GPU.

Железо и окружение

GPU: NVIDIA GeForce RTX 5060 Ti

Все измерения проводились в FP32, модель запускалась в eval() и через torch.inference_mode().

Также были отключены:

torch.backends.cudnn.benchmark = False
torch.backends.cudnn.allow_tf32 = False
torch.backends.cuda.matmul.allow_tf32 = False

Модель

Используется последовательная CNN без residual connections.

Основные слои:

Conv 7x7, 3 -> 32, stride 2
ReLU
MaxPool 3x3, stride 2

Conv 5x5, 32 -> 64
BatchNorm
ReLU

Conv 3x3, 64 -> 128, stride 2
ReLU

Conv 1x1, 128 -> 256
ReLU

Conv 3x3, 256 -> 256, stride 2
BatchNorm
ReLU

Conv 1x1, 256 -> 512
BatchNorm
ReLU

AdaptiveAvgPool2d(1)

ReLU
Linear 256 -> 100

FLOPs

Использовал соглашение:

1 MAC = 2 FLOPs

После подсчёта всех слоёв получилась формула:

[
F(I, B) = B(17779I^2 + 313600)
]

где:

I — размер изображения;

B — batch size.

Основная часть FLOPs ожидаемо приходится на свёртки.

Memory

Для memory использовал упрощение из задания: считаются веса модели и сумма всех активаций.

Получилась формула:

[
M(I, B) = 4,174,632 + 4B(33I^2 + 868)
]

Результат возвращается в байтах.

Эта формула специально довольно грубая. В реальном inference PyTorch может освобождать и переиспользовать память промежуточных тензоров, поэтому реальное потребление памяти может быть меньше.

Bytes moved

Для latency и energy дополнительно посчитал примерное количество перемещаемых данных.

Кеширование не учитывал и считал worst case: каждый слой читает input и веса и записывает output.

Получилась формула:

[
Q(I, B) = 4(105BI^2 + 2148B + 1,043,652)
]

Latency

Для latency использовал модель:

[
L(I,B) =
t_0 +
\max(
\alpha F(I,B),
\beta Q(I,B)
)
]

Здесь:

t0 — постоянный overhead;

alpha — коэффициент, связанный со скоростью вычислений;

beta — коэффициент, связанный со скоростью работы с памятью.

Параметры после калибровки:

t0    = 4.960041254945872e-14
alpha = 6.760330254286694e-13
beta  = 2.433848152194495e-11

Energy

Для энергии использовал простую линейную модель:

[
E(I,B) =
e_0 +
e_{flop}F(I,B) +
e_{byte}Q(I,B)
]

После калибровки получились:

e0     = 3.093045859483107e-17
e_flop = 4.851076741295402e-11
e_byte = 3.1221781838038766e-18

Измерения

Проверял разные значения размера изображения и batch size.

Размеры изображений:

32, 64, 80, 96, 128, 224, 256, 384, 400, 416, 512, 1024

Batch size:

1, 2, 4, 8, 16, 18, 32, 64, 88, 128, 130, 256, 512

Для каждой конфигурации сохранялись:

latency;

peak memory;

energy;

был ли OOM;

является ли точка validation.

Результаты лежат в:

results/measurements.csv

Что получилось

На моей сетке OOM реально произошёл на:

image_size = 1024
batch = 512

При этом аналитическая модель memory иногда предсказывает OOM раньше, чем он реально происходит.

Это связано с тем, что в аналитической формуле я складываю все активации, а при реальном inference они не обязаны одновременно находиться в памяти.

Для latency простая формула в целом показывает рост времени при увеличении I и B, но не может идеально повторять реальный GPU.

Причина в том, что реальная скорость зависит не только от FLOPs и количества перемещаемых байт, но ещё от CUDA kernels, cuDNN, размеров тензоров, кешей и других деталей реализации.

Для energy ситуация похожая. На маленьких входах измерение энергии получается довольно шумным, поэтому модель лучше описывает более тяжёлые конфигурации.

В целом FLOPs предсказываются наиболее просто и точно, потому что они напрямую определяются архитектурой. Memory, latency и energy уже заметно сильнее зависят от того, как именно PyTorch и CUDA выполняют сеть.

Как запустить

Установить зависимости:

pip install torch numpy pandas scipy matplotlib nvidia-ml-py

Дальше запустить измерения и калибровку.

Для notebook, достаточно выполнить ячейки сверху вниз.

После запуска должны появиться:

results/
├── measurements.csv
├── theta.json
└── figures/

В theta.json лежат найденные параметры для latency и energy.

В figures/ лежат графики с реальными измерениями и предсказаниями аналитической модели.
